# 项目说明

> 本项目是来源于 [88api.ai Token 聚合站](https://88api.ai/) 的生图插件仓库，同时适配 Codex、Claude Code、Cursor 和 Hermes。

项目以 `88API-image-gen` 为统一品牌，为各 AI 客户端提供图像生成、图像编辑和批量生产工作流。

## 首次安装流程

用户可以把当前仓库地址交给 Codex，并要求安装 `88api-image-gen`。完整安装流程包括：

1. 检查 Node.js 18+；本插件不依赖 Python。
2. 添加仓库 marketplace 并安装 `88api-image-gen@88api-plugins`。
3. 检查 Windows PowerShell、macOS `sips` 或 Linux ImageMagick 图片处理环境。
4. 运行 `--get-config` 检查本地是否已经配置 88API Key，以及 API 根地址是否正确。
5. 如果没有 Key，提醒用户访问 [88api.ai](https://88api.ai/) 创建“生图分组 Key”，再使用 `--set-key` 写入本机配置。
6. 默认 API 根地址为 `https://88api.ai`。若用户需要兼容网关 / 镜像，使用 `--set-api-root <完整 http(s) URL>` 持久化保存；要求与配置 Key 一样写入本机配置文件，不得写入仓库。

创建和复制生图分组 Key 的图文步骤见仓库根目录 [README 的首次配置 Key 教程](../README.md#首次配置-key)。教程截图保存在 `docs/assets/`，随仓库一起发布，GitHub 和 Codex 均可直接读取。自定义 API 根地址说明见 README 中「可选：自定义 API 根地址」。

一个 Key 即可正常使用。需要同时生成多张独立图片时才配置多个 Key，最多 10 个。

> **高风险提醒：低配置电脑切勿尝试批量生图或多 worker 高并发。** 本地内存可能被大量图片响应和参考图缓冲占满，导致电脑卡死或 Codex 客户端崩溃。本地崩溃不会自动取消已经提交到 88API 云端的请求；云端已受理或完成的任务仍可能计费，即使图片最终没有成功保存到本机。默认应使用单 Key、单 worker、`--concurrency 1`，批量工作流必须先 `--dry-run`。

真实 Key 只能写入用户本机的 `~/.agents/88api-image-gen-config.json`，不得写入项目源码、README、提交记录或日志。

## 这个仓库是什么

这是一个多客户端 AI 插件仓库，目前只提供一个插件：

- `88api-image-gen`

核心脚本 `plugins/88api-image-gen/scripts/generate.mjs` 只有一份，各客户端通过薄入口接入：

- Codex：`.agents/plugins/marketplace.json` + `plugins/88api-image-gen/.codex-plugin/plugin.json`
- Claude Code：`.claude-plugin/marketplace.json` + `.claude-plugin/plugin.json`
- Cursor：`.cursor-plugin/plugin.json`
- Hermes / Claude / Cursor 共享：`skills/88api-image-gen/SKILL.md` + `install.sh` / `install.ps1`
- Hermes 桌面面板：`hermes-desktop-plugin/plugin.js`

marketplace 信息（Codex 与 Claude 共用名称）：

- 名称：`88api-plugins`
- 展示名：`88API Plugins`

## 关键文件作用

### `.agents/plugins/marketplace.json`

定义 marketplace 名称、展示名，以及本仓库中登记的插件列表。

### `plugins/88api-image-gen/.codex-plugin/plugin.json`

插件元数据，包括：

- 插件名
- 版本号
- marketplace 中显示的描述
- logo / composer icon

### `plugins/88api-image-gen/scripts/generate.mjs`

插件核心脚本，负责：

- 配置读取与写入（worker Key、`apiRoot` / `--set-api-root`）
- 文生图
- 图生图
- 多 worker 调度
- 批量任务编排
- 工作流补洞与结果清单输出

### `plugins/88api-image-gen/skills/88api-image-gen/SKILL.md`

给 Codex 的技能说明文件，用来告诉模型这个插件应该怎么触发、如何调用、支持哪些参数与限制。

### `README.md`

对普通使用者的中文说明文档。

### `docs/更新说明-v0.1.1.md`

记录 `0.1.0 -> 0.1.1` 的主要变化。

### `docs/更新说明-v0.2.0.md`

记录插件升级为 `88api-image-gen`、切换 88API 接口和完善首次安装流程的主要变化。

### `docs/更新说明-v0.2.1.md`

记录首次配置检查和 worker 列表中文化的变化。

### `docs/更新说明-v0.3.0.md`

记录 `gpt-image-2` Images API 传输和批量资源优化。

### `docs/更新说明-v0.4.0.md`

记录 Image2 Images API 原生 SSE、Codex 提示词编排和费用安全策略。

### `docs/更新说明-v0.5.0.md`

记录多客户端适配（Claude Code / Cursor / Hermes）、配置目录迁移到 `~/.agents/` 和安装脚本。

### `docs/项目说明.md`

解释仓库结构和文件职责，也就是你现在看到的这份文档。

## 对外发布内容

公开仓库与发布归档只保留对使用者有价值的内容：

- marketplace 配置
- 插件主体代码
- 公开文档
- 版本信息

不会放进公开仓库的内容：

- 真实 API Key
- 本机私有路径素材
- 运行日志
- 生图产物
- 本地缓存
- 仅用于内部实验的临时文件

## 版本管理方式

当前项目建议按两层管理：

### 1. 开发副本

用于继续开发、验证、实验和同步 GitHub 更新。

### 2. 版本归档

用于冻结某个稳定版本，方便回溯和复现。归档目录不再继续开发，也不保留 `.git`。

## 当前版本定位

`0.5.0` 的定位是：

- 核心生图模型为 `gpt-image-2`
- 所有任务只使用 Image2 Images API，不需要 GPT 文本模型权限
- 单张文生图可按需开启 Images API 原生 partial-image 预览
- 由当前会话模型负责提示词整理和受控多轮编排
- 已受理或状态未知的付费请求禁止自动重发或跨接口回退
- 一个仓库同时适配 Codex、Claude Code、Cursor、Hermes，核心脚本保持单份
- 配置目录统一为 `~/.agents/`，旧 `~/.codex/` 配置自动迁移
- 提供 `install.sh` / `install.ps1` 一键接入多个客户端
- Hermes 桌面面板以命令生成器形态提供图形化入口
- 把多 worker 调度正式做进插件
- 把通用批量图生图工作流抽象出来
- 把公开仓库整理成可直接给别人安装和使用的状态

## 使用者需要知道的最少信息

如果你是 Codex 用户，记住这两条命令就够了：

```bash
codex plugin marketplace add DaYePython/88API-image-gen
codex plugin add 88api-image-gen@88api-plugins
```

其他客户端（Claude Code / Cursor / Hermes）克隆仓库后运行 `bash install.sh` 即可。

更完整的使用方式，请看仓库根目录 [README.md](../README.md)。
